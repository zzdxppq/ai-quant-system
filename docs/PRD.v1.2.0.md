# AI 量化周期看板 — 产品需求文档 (PRD)

> 版本：1.2.0 | 日期：2026-05-26 | 状态：已实现（本轮同步：调度时间校正/API扩展/三板组/午间排行/趋势回填链路）

---

## 1. 产品概述

### 1.1 产品定位

面向 A 股短线交易者的**周期识别 + 量化选股**辅助决策系统。系统通过跟踪全市场 10 日涨幅排行，自动识别市场所处的周期阶段，并在关键时点（9:27 竞价结束后）执行选股筛选，最终通过三层交叉验证输出操作信号和仓位建议。

### 1.2 目标用户

A 股短线交易者，交易体系以**周期轮回 + 弹性股 + 龙妖股**为核心，偏好主板连板股、关注创业板 20CM/30CM 机会。

### 1.3 核心价值

| 价值点 | 描述 |
|--------|------|
| 周期感知 | 将主观经验（"市场现在什么阶段"）量化为 7 个离散状态，消除情绪干扰 |
| 机械选股 | 替代手工盯盘，9:27 自动输出符合条件的标的 |
| 信号分级 | 将"能不能做 / 做多少仓位"标准化为 strong / normal / watch / avoid 四级 |
| 龙头晴雨表 | 高标龙头竞价反馈一票否决机制，避免逆势操作 |
| 过热过滤 | 240 周线偏离度检测，排除严重超涨标的 |

## 2. 功能需求

### 2.1 周期引擎（Cycle Engine）

**目标**：实时判定市场所处的周期阶段。

**周期状态机（7 阶段）**：

```
孕育期 → 小周期启动 → 小周期完成 → 完整周期 → 余温期 → 退潮期 → (回到孕育期)
                ↘ 混沌期 ↗
```

| 阶段 | 进入条件 | 含义 |
|------|----------|------|
| 孕育期 | 无标的 10 日涨幅 > 45% | 市场缺乏领涨标的，不操作 |
| 小周期启动 | 有标的 > 45% 且持续 >= 3 天 | 出现领涨种子，可试探 |
| 混沌期 | 前任未达 100% 即回落，新标的接榜亦未达 100% | 方向不明，极度谨慎 |
| 小周期完成 | 榜首标的 > 100% | 周期得到确认 |
| 完整周期 | 榜首 > 120% 且站榜首 >= 3 天 | 最佳操作窗口 |
| 余温期 | 代表股涨速放缓（< 峰值的 90%） | 持股为主，不追高 |
| 退潮期 | 代表股跌出榜首 | 观望，等待新周期 |

**输入**：全市场 10 日涨幅排行 DataFrame（code, name, gain_10d, is_main_board）

**输出**：CycleSnapshot（日期、阶段、阶段天数、代表股、候选池 Top20、上轮周期信息）

**配置参数**：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| gain_threshold_start | 45% | 小周期启动阈值 |
| gain_threshold_complete | 100% | 小周期完成阈值 |
| gain_threshold_full | 120% | 完整周期阈值 |
| sustain_days_start | 3 天 | 启动持续天数要求 |
| sustain_days_full | 3 天 | 完整周期榜首天数要求 |
| tracking_threshold | 40% | 进入跟踪池的最低涨幅 |

**持久化**：JSON 文件（`data/cycle_state.json`），支持重启恢复。

### 2.2 选股引擎（Screener Engine）

**目标**：每日 9:27 竞价结束后，筛选出符合条件的短线标的。

**执行时间**：交易日 9:27（`SCREENER_CRON_HOUR` / `SCREENER_CRON_MINUTE`，见 `src/config.py`）

**筛选逻辑（与 `src/engine/screener.py` + `SCREENER_CONFIG` 一致）**  

实现对应通达信 LIANBAN / PD1~PD4 / 量比等口径；**默认参数以 `SCREENER_CONFIG` 为准**（下表为当前默认值）。

| 步骤 | 规则 | 默认阈值 / 配置键 | 说明 |
|------|------|-------------------|------|
| 0 | 连板候选池 | `min_continuous_limit_up: 2` | 由 **`_detect_continuous_limit_up`** 从涨停池历史计算：从**昨日**涨停池起向前回溯连续涨停日数，**今日是否涨停不参与计数**；仅 `continuous_limit_up >= min_continuous_limit_up` 的代码进入后续。 |
| 0.5 | 定向补齐行情 | — | 东财全市场快照常仅覆盖涨幅前列，二连板候选易不在 `realtime_df` 中；对「已合格但缺行」的股票 **`fetch_realtime_batch` 新浪补齐**后再筛。新浪行可能缺 `turnover`/`market_cap`/`volume_ratio`，与下方**软过滤**一致。 |
| 1 | 板块/名称排除 | `exclude_st` / `exclude_kcb` / `exclude_cyb` / `exclude_bse` | 默认：`ST/*ST`、**688**、**300/301**、**8/4 北交所** 排除。 |
| 2 | 有效竞价价 | — | `pre_close > 0` 且 `open > 0`，否则剔除。 |
| 3 | 竞价涨幅 | `auction_gain_min` ~ `auction_gain_max` | **4% ~ 7.5%**：`(open/pre_close-1)*100`。 |
| 4 | 竞价换手率（软） | `auction_turnover_min: 0.5` | 若 `market_cap`（元）>0：`竞价换手 ≈ amount/MV*100`；否则用行情 `turnover`。**仅当算出的换手 >0 且 <0.5% 时剔除**；无法可靠计算则**放行**。 |
| 5 | 竞价成交量（手） | `auction_volume_lots_min: 1000` | 通达信 **JJL ≈ amount/pre_close/100**（手）；**< 1000 手剔除**（对应原公式 PD1「成交量」门槛，**非**单独一行「竞价金额>1000 万元」）。 |
| 6 | 流通市值（软） | `market_cap_min` ~ `market_cap_max` | 默认 **>20 亿且 <100 亿**（亿由元/列换算）。**市值缺失或不可算则放行**，避免误杀。 |
| 7 | 量比（软） | `volume_ratio_min: 1.0` | **9:25–9:30**：用竞价量与 **5 日日均量/240** 自算竞价量比；**非竞价时段**用行情 `volume_ratio` 或 **JJL 与 5 日均量**估算。**仅当量比 >0 且 <1.0 时剔除**；缺失则放行。 |

**命中排序**：按 **连板数降序、再按竞价涨幅降序**。

**输入**：
- 实时行情 DataFrame（列含 `code, name, open, pre_close, close, volume, amount, turnover, market_cap, volume_ratio, gain_10d` 等；以调度器/拉取层实际列为准）
- `limit_up_history`：近若干日涨停池 `{date_str: DataFrame}`，供连板检测
- `cycle_codes`：周期代表/候选代码列表，用于 **`matched_cycle`** 标记（不参与是否入选）

**输出**：`ScreenerHit`（代码、名称、连板数、开盘价、竞价涨幅%、竞价换手%、竞价金额(万元)、竞价成交量(手)、**竞价量比**、流通市值(亿，可空)、量比、10 日涨幅、是否周期匹配）

> **说明**：产品早期文档「七层过滤」为通达信口诀概括；当前代码在 7 条硬条件之外还有 **定向补齐** 与多处 **软过滤（有值才卡阈值）**，上表按**真实执行顺序**编排以便评审与对码。

#### 2.2.1 选股记录（screener_history）与「昨日选股今日竞价」

**目标**：持久化每日 9:27 命中标的，支撑看板「昨日选股今日竞价」表与胜率统计。

| 能力 | 说明 |
|------|------|
| 归档 | 选股执行后写入 `screener_history`（JSON / 分析库表），含竞价字段、`status`：`pending`→`closed`→`settled` |
| 收盘回填 | `backfill_close`：按日 K / 现货补 **`close_price`、`day_change`** 等 |
| 次日竞价 | `backfill_next_day_auction`：补 **`next_day_open`、`next_day_auction_gain`** 等 |
| **历史补缺** | `repair_missing_close_prices`：对 **`date < 今天` 且仍缺 `close_price`** 的记录按日 K 幂等补缺；在 **`GET /api/screener-history`** 与 **`backfill_close`** 链路中触发，避免漏跑导致「昨日收盘」长期为「—」 |

**看板展示**：仅交易日且存在昨日归档记录时展示该表；列含昨日竞价/收盘、今日开盘与竞价相对昨收、温和开仓判定、次日收盘涨幅等。

### 2.3 高标龙头竞价反馈（Leader Feedback）

**目标**：以 10 日涨幅榜第一（高标龙头）的竞价表现作为全市场情绪的晴雨表。

**判定规则**：

| 竞价涨跌幅 | 信号 | 操作建议 | 一票否决 |
|------------|------|----------|----------|
| 跌停（±0.5%） | 跌停 | 不操作 | 是 |
| < -3% | 负反馈 | 不操作 | 是 |
| -3% ~ 0% | 中性 | 谨慎参与 | 否 |
| 0% ~ 3% | 正反馈 | 正常参与 | 否 |
| > 3% | 强正反馈 | 积极参与 | 否 |

**一票否决机制**：当龙头信号为"跌停"或"负反馈"时，当日所有选股标的信号强制降为 avoid，不开仓。

---

### 2.4 交叉验证引擎（Cross Validator）

**目标**：将周期状态、龙头反馈、选股结果三层信号交叉，输出最终操作建议。

**三层过滤**：

```
第 1 层：周期状态（大环境）→ 决定基础操作倾向
第 2 层：龙头竞价反馈（情绪晴雨表）→ 一票否决 or 调节激进程度
第 3 层：选股公式命中（标的层面）→ 决定具体标的
```

**信号等级与仓位建议**：

| 周期阶段 | 是否代表股 | 龙头反馈 | 信号 | 建议仓位 |
|----------|-----------|----------|------|----------|
| 完整周期/小周期完成 | 是 | 积极 | strong | 6-9 层 |
| 完整周期/小周期完成 | 是 | 正常 | strong | 6 层（底仓 3 + 确认加仓 3） |
| 完整周期/小周期完成 | 是 | 谨慎 | normal | 3-4 层 |
| 完整周期/小周期完成 | 否（候选） | — | normal | 3 层底仓 |
| 完整周期/小周期完成 | 否（非周期） | — | watch | 2 层试探 |
| 小周期启动 | 候选 | 积极 | normal | 3-4 层 |
| 小周期启动 | 候选 | 谨慎 | watch | 2 层观察 |
| 小周期启动 | 非周期 | — | watch | 1-2 层 |
| 混沌期 | 候选 | — | watch | 1-2 层 |
| 混沌期 | 非候选 | — | avoid | 不开仓 |
| 余温期 | — | — | watch | 持有不加仓 |
| 退潮期/孕育期 | — | — | avoid | 不开仓 |

#### 2.4.1 决策快照与看板指标（daily_advice / 参考带）

**目标**：将复盘与情绪指标收敛为可刷新的一张「决策卡」，并与旧版 sentiment 英雄条并存或切换展示。

| 能力 | 说明 |
|------|------|
| 决策快照 | `latest_advice` / 决策 API：仓位建议、理由、**参与带 + 参考带** 结构化指标 |
| **昨日炸板 × 今日一字** | 参考带内 **「昨日炸板平均反馈」与「今日一字涨停」同一指标格内分左右两区**：左为炸板反馈（%），右为一字家数（可点击打开一字列表）；避免单行混排难以阅读 |
| 一字列表 | 与 sentiment 池 **`limit_up_flat_list`** 联动弹窗，展示竞价封死样本 |

### 2.5 240 周线偏离度过滤（MA Deviation）

**目标**：对选股结果进行二次过滤，排除偏离长期均线过远（过热）的标的。

**计算公式**：

```
偏离度 = (当前价 - MA240W) / MA240W × 100%
```

- MA240W = 近 240 周收盘价均值（约 5 年均价）
- 偏离度 > 100% → 标记"偏离过大"，降级或排除
- 数据不足 20 周 → 跳过检测（默认通过）

### 2.6 回测引擎（Backtest Engine）

**目标**：验证"周期识别 + 选股公式"交叉策略的历史胜率和盈亏比。

**交易规则**：

| 项目 | 规则 |
|------|------|
| 买入信号 | strong → 6 层仓位；normal → 3 层仓位 |
| 不交易 | watch / avoid 信号 |
| 止盈 | +10%（主板一个涨停） |
| 止损 | -5% |
| 最大持有天数 | 3 天（短线） |
| 初始资金 | 100 万 |

**统计指标**：
- 总交易数、胜率、盈亏比
- 平均盈利%、平均亏损%
- 最大连胜/连亏
- 总收益率、最大回撤
- 按周期阶段分组统计
- 每日权益曲线

### 2.7 数据层（Data Layer）

**说明**：v1.0 文档以 AKShare 为主描述；**当前实现**以 **httpx 直连东方财富 / 新浪 / 腾讯** 等接口为主（具体以 `src/data/*_api.py` 为准），AKShare 可能仍存在于部分脚本或兼容路径。

**数据源（概念对齐）**：

| 接口（示例 / 历史） | 用途 |
|------|------|
| `stock_zh_a_spot_em` | 全市场实时快照 |
| `stock_zt_pool_em` | 涨停板池 |
| `stock_zh_a_hist` | 个股历史日线/周线 |
| `stock_rank_lxsz_ths` | 同花顺连续上涨排行 |
| `tool_trade_date_hist_sina` | 交易日历 |

**降级策略**：
- 网络失败 → 自动降级为 Mock 数据
- 环境变量 `MOCK=1` → 强制使用模拟数据
- Mock 支持 6 种场景（孕育/小周期启动/小周期完成/完整周期/混沌/退潮）

**存储（实际实现与本文档 v1.0 差异说明）**：
- **业务快照**：`data/*.json`（如 `latest_snapshot.json`、`latest_ranking.json`、`latest_screener.json` 等）及 **DuckDB `quant.duckdb`** 中的文档表 / 分析表（如 `screener_history_entry`、`minute_kline`），由 `json_io` / `analytics_store` 等统一读写；单机场景下注意 **库文件单写者**，避免多进程占库导致 `IO Error`。
- **分析侧日级 blob**：部分 JSON 摘要写入 DuckDB 日表时采用 **按 `blob_kind`+`blob_date` 先 DELETE 再 INSERT**，避免旧库缺少 UNIQUE 时 `ON CONFLICT` 绑定失败。

**分时（minute）**：
- 拉取：腾讯分时 JSON → 可选落库 `minute_kline`（**仅存 `seq` 与价量等，不存 bar 时间字符串**）。
- 读出：`load_minute_payload` 用 **`seq` 按 A 股连续交易分钟还原 `t`（HH:MM）**（上午含 9:30–11:30 共 121 根序，下午接 13:00 起），并修正 **`pre_close` 等列与行字段对齐**；保证看板 K 线弹窗「分时」在 **走缓存** 时仍可画价线与**量能柱**（配色：相对前一分钟涨跌红/绿）。

### 2.8 定时调度（Scheduler）

| 任务 | 执行时间 | 内容 |
|------|----------|------|
| 周期更新 | 周一至周五 15:30 | 拉取行情 → 计算 10 日涨幅 → 更新状态机 → 保存快照；**收盘 ranking 落库后执行趋势选股**（见 §2.10） |
| 选股执行 | 周一至周五 9:27 | 拉取竞价数据 → 连板检测 → 龙头反馈 → 选股筛选 → 偏离度过滤 → 交叉验证 |

支持命令行手动触发：`--update`（周期更新）、`--screen`（选股）

### 2.10 趋势选股（明日观察池）

**目标**：在 **TOP30 日收盘 ranking** 初筛通过的标的中，按规则打分，**每日仅 1 只**进入「明日观察池」，并滚动记录历史用于胜率复盘。

**执行时机**：与周期更新同源，在 **`latest_ranking.json` 落库之后** 执行（避免用午间未收盘榜）。

**初筛要点（与引擎一致）**：10 日涨幅、当日涨幅、连板与涨停关系、收盘 vs MA5/MA10、换手率区间等。

**评分**：基础分项 + 板块动量修正；**取 `total_score` 最高 1 只**写入 `latest_trend.json` 的 `pool`，全量评分在 `all_scored`。

**入选日（`date`）口径（重要）**：
- **`trend_history` 每条记录的 `date` = 榜单所属交易日**，取自 **`latest_ranking.json` 的 `trade_date` / `date` / `updated_at` 的日期部分**（`YYYY-MM-DD`），**不取运行时刻自然日**；避免 5/14 收盘榜在 5/15 凌晨跑任务却被记成 5/15。
- **`latest_trend.json` 的 `date`** 与上述一致。
- **板块占比历史 `trend_sector_history.json`** 的键与榜单日对齐。

**历史表 `trend_history.json`**：
- 每日最多 **1** 笔；若因重复跑产生同日多条，**`reconcile` / API 读取时按日去重，仅保留当日 `total_score` 最高的一条**。
- **纠错**：若 `latest_trend.date` 晚于 ranking 交易日且历史同码挂了错误日期，**一次性将历史 `date` 对齐回 ranking 日**。

**次日与持仓第二日（用于胜率）**：

| 字段含义 | 口径 |
|----------|------|
| D+1 | 相对 **入选日收盘** 的次日开盘/收盘；`is_win` = D+1 收盘相对入选日收盘 **> 0** |
| 温和开仓 | 次日竞价相对入选日收盘 **∈ [-3%, +3%]** |
| D+2 | 假设以 **D+1 收盘价** 买入，再下一日开盘/收盘相对买入价；**`is_win_after_entry` = D+2 收盘 > 0** |

**回填**：`backfill_trend_next_day` 用日 K 填 D+1/D+2；**不因周末跳过**（任意自然日可拉 K 线结算）；**东财日 K 失败则新浪日 K 兜底**；K 线按日期升序对齐后取 `rec_date` 的下 1、2 根。竞价时段可由 `backfill_trend_morning_auction` 用现货开盘先填次日竞价%，收盘后由日 K 覆盖。

**API**：`GET /api/trend-history` 在线程池中调用 **`get_trend_history_payload()`**：去重落盘 → 回填 → 再读入并计算统计（含 **≥85 / <85 分档 D+1 胜率** 等）。

**手动触发**：`POST /api/trend-run` → `run_trend_screener` + `backfill_trend_next_day`。

## 3. 非功能需求

| 项目 | 要求 |
|------|------|
| 可用性 | 网络断开时自动降级为 Mock 模式，不影响系统运行 |
| 性能 | 周期更新 < 30s，选股筛选 < 60s（含数据拉取） |
| 持久化 | 周期状态 JSON 持久化，支持进程重启后恢复 |
| 可配置 | 所有阈值参数集中于 `src/config.py`，修改无需改动业务代码 |
| 可观测 | 6 个 JSON 文件记录最新运行结果，API 可查询 |
| 历史追溯 | 保留最近 60 天周期快照时间线 |
| 趋势历史一致性 | 榜单日与历史 `date` 对齐；同日多条合并为最高分 1 笔；API 侧自动回填 D+1/D+2 |
| 选股历史完整性 | 缺收盘的归档记录在拉取 `screener-history` 时尽量按日 K 补缺 |

## 4. 约束与限制

1. **数据源限制**：AKShare 依赖东方财富公开数据，有频率限制，非实时 Tick 级
2. **选股时效性**：9:27 竞价数据为估算值，开盘后可能变化
3. **回测简化**：当前回测仅使用代表股开仓，未覆盖全选股结果
4. **单机部署**：`quant.duckdb` 与 JSON 快照适合单用户；**避免多进程同时打开同一库文件**（否则可能出现文件锁 IO 错误）
5. **默认排除创业板/科创板**：配置可修改，但默认保守策略
